# 🛡️ Academic VPN Project

> A production-style academic VPN system built by **Muntazir Mehdi** — combining custom cryptography, a real SOCKS5 proxy, a FastAPI backend, and a live SOC (Security Operations Center) dashboard.

This project is designed for educational and research purposes to demonstrate real-world VPN architecture, cryptographic algorithm design, network routing, and threat detection — all in one integrated system.

---

## 📸 Dashboard Preview

The VPN ships with a full **CyberCommand SOC** web dashboard, accessible at `http://localhost:8000` after starting the server. It features:

- Live traffic graph (Chart.js + WebSocket)
- World map with animated VPN tunnel routes (Leaflet.js)
- Real-time connection metrics (bytes in/out, active connections)
- Encryption algorithm selector
- Handshake status panel
- Threat/IDS event feed

## 🏗️ Project Overview

This project implements a functioning VPN-like system at the application layer. It includes:

| Layer | What It Does |
|---|---|
| **Cryptography** | Custom AES, DES, 3DES, ChaCha20, SHA-256, RSA, Digital Signatures |
| **Proxy** | Real SOCKS5 proxy server (RFC 1928) with username/password auth |
| **Tunnel** | WireGuard-style protocol using ChaCha20, Wintun TUN driver integration |
| **Network** | Routing manager, split tunneling, kill switch (Windows Firewall) |
| **Security** | Signature-based + heuristic IDS, SQLite threat log, user authentication |
| **API** | FastAPI REST + WebSocket backend |
| **Frontend** | React + TailwindCSS SOC dashboard served by the backend |
| **Access** | ngrok TCP tunnel for exposing the proxy publicly |

## ⚡ Quick Start

### Requirements

- **Windows** (kill switch, routing, Wintun features require Windows)
- **Python 3.11+** recommended
- Administrator privileges (required for routing, kill switch, Wintun)

### 1. Create and activate a virtual environment

```powershell
python -m venv venv
.\venv\Scripts\Activate.ps1
```

### 2. Install dependencies

```bash
pip install -r backend/requirements.txt
```

### 3. Start the VPN server

```bash
python -m backend.server
```

Or use the convenience launchers:

```bash
python run_server.py
# or double-click:
START_SERVER.bat
```

The server starts on `http://localhost:8000` and **automatically opens the SOC dashboard** in your browser.

### 4. Connect with the VPN client (optional CLI mode)

```bash
python backend/vpn_client.py
# or:
python launch_vpn.py
START_VPN_ADMIN.bat
```

### 5. Configure your system's proxy

Point your OS or browser's SOCKS5 proxy to:

```
Host: localhost (or the ngrok TCP address shown on the dashboard)
Port: 1080
Username: admin
Password: <auto-generated, shown at startup / on /status endpoint>
```

## 🔐 Core Features

### Cryptography (`core/`)

All ciphers extend an abstract `CipherInterface` base class with a uniform `encrypt(data, key)` / `decrypt(data, key)` API.

| Module | Algorithm | Standard | Notes |
|---|---|---|---|
| `aes.py` | AES-128 | FIPS 197 | 10-round key expansion, SubBytes, ShiftRows, MixColumns, AddRoundKey |
| `des.py` | DES | Educational | Functional encrypt/decrypt; FIPS vector mismatch (see Known Issues) |
| `triple_des.py` | 3DES | Verified | Encrypt-Decrypt-Encrypt (EDE) using DES core |
| `chacha20.py` | ChaCha20 | RFC 7539/8439 | 256-bit key, 96-bit nonce, 20-round quarter-round ARX |
| `hashing.py` | SHA-256 | FIPS 180-4 | Full implementation, verified against test vectors |
| `rsa.py` | RSA | — | Key generation and encryption/decryption |
| `signatures.py` | Digital Signatures | — | Sign and verify using RSA + SHA-256 |

### SOCKS5 Proxy (`backend/proxy.py`)

A real RFC 1928 SOCKS5 proxy server implementation:

- **Username/Password authentication** (RFC 1929) — credentials auto-generated on startup
- Supports `CONNECT` commands for IPv4, IPv6, and domain name address types
- Bidirectional `select`-based data relay loop
- Live stats callbacks: bytes in/out, active connections
- Packet inspection hooks (for IDS integration)
- Binds to `0.0.0.0:1080` to accept LAN/external connections

### FastAPI Backend (`backend/server.py`)

| Endpoint | Method | Description |
|---|---|---|
| `/` | GET | Serves the SOC frontend dashboard |
| `/status` | GET | Full VPN state: traffic, connections, handshake, proxy credentials, ngrok URL |
| `/start` | POST | Start the SOCKS5 proxy service |
| `/stop` | POST | Stop the SOCKS5 proxy service |
| `/config` | POST | Switch encryption algorithm (AES / DES / 3DES / ChaCha20) |
| `/threats` | GET | In-memory threat event list |
| `/api/login` | POST | Authenticate user against SQLite DB |
| `/api/admin/threats` | GET | Persistent threat log from SQLite (last 50) |
| `/ws/traffic` | WebSocket | Real-time push: bytes, handshake status, algorithm, threats, latency |

### Kill Switch (`backend/kill_switch.py`)

Windows Firewall-based kill switch using `netsh advfirewall`:

- **ALLOW** rule: VPN server IP + port (UDP)
- **ALLOW** rule: Local network ranges (RFC 1918)
- **BLOCK** rule: All other outbound traffic
- Automatically cleans up rules on disable/re-enable

### Split Tunneling (`backend/split_tunnel.py`)

Route specific domains outside the VPN tunnel:

- Resolves domain to IP via DNS
- Adds/removes per-host routes via the Windows `route` command through the original gateway
- Tracks active bypass domains and their resolved IPs

### Routing Manager (`backend/routing_manager.py`)

Manages the Windows routing table for full-tunnel VPN mode:

- Detects and backs up the current default gateway
- Configures the Wintun TUN interface IP via `netsh`
- Adds split-default routes (`0.0.0.0/1` + `128.0.0.0/1`) through the VPN gateway
- Sets VPN DNS servers (default: Cloudflare `1.1.1.1` / `1.0.0.1`)
- Restores original routes on disconnect

### Intrusion Detection System (`core/ids.py`)

Signature-based + heuristic packet scanner:

| Detection Type | Examples |
|---|---|
| SQL Injection | `UNION SELECT`, `DROP TABLE` |
| XSS | `<script>` tags |
| Directory Traversal | `../` patterns |
| Remote Code Execution | `eval(` patterns |
| Heuristic | Anomalous traffic pattern (2% random flagging for demo) |

Threat events include timestamp, threat type, severity (`CRITICAL` / `HIGH` / `MEDIUM`), simulated source IP, and action (`BLOCKED` / `FLAGGED`). Events are persisted to SQLite via `backend/database.py`.

### WireGuard-Style Protocol (`core/wireguard.py`)

A simplified WireGuard-inspired protocol using the custom ChaCha20 implementation:

- Handshake initiation / response message types
- Session key management
- Data packet framing with ChaCha20 encryption

### Wintun Integration (`core/wintun_wrapper.py` + `wintun/`)

Wraps the [Wintun](https://www.wintun.net/) Windows TUN driver for Layer 3 packet handling. Provides the virtual network adapter used for routing all system traffic through the VPN tunnel.

### Database and Authentication (`backend/database.py`)

SQLite database (`vpn_data.db`) with two tables:

- **users** — username, SHA-256 hashed password, role (`admin` / `user`). Default account: `admin` / `admin`.
- **threats** — persistent IDS event log (timestamp, type, source IP, severity, action)

### ngrok Public Tunnel (`backend/server.py`)

On startup the server attempts to open a public `ngrok` TCP tunnel on port 1080. The public URL is exposed via `/status` and displayed on the dashboard, allowing remote SOCKS5 connections without port forwarding.

## ⚠️ Known Issues and Limitations

| Issue | Details |
|---|---|
| **DES FIPS vector mismatch** | The DES implementation correctly encrypts and decrypts (round-trip works), but produces different ciphertext than the official NIST/FIPS vectors. This is likely due to a variation in key padding or bit ordering. Fully functional for demonstration purposes. |
| **Windows-only for routing/kill switch** | The Kill Switch, Split Tunneling, and Routing Manager modules use Windows-specific commands (`netsh`, `route`). They will not function on Linux/macOS. |
| **Wintun requires admin** | Creating a TUN adapter with the Wintun driver requires Administrator privileges. Run `START_VPN_ADMIN.bat` or your terminal as Administrator. |
| **ngrok requires authtoken** | The public TCP tunnel via ngrok requires a free ngrok account and `ngrok config add-authtoken <token>`. Without it, the tunnel silently fails and the proxy remains LAN-only. |
| **Simulated JWT** | The `/api/login` endpoint returns a hardcoded `"simulated-jwt-token"` string. Token validation is not implemented; the frontend uses it as a flag only. |
| **IDS heuristic is randomized** | 2% of all packets are randomly flagged as "Anomalous Traffic Pattern" regardless of content. This is intentional for demo/visualization purposes. |
| **ChaCha20 zero-nonce default** | If no nonce is provided to `ChaCha20.encrypt()`, a zero nonce is used. This is insecure in production and noted in the code. |
| **SHA-256 password hashing** | `database.py` uses plain SHA-256 for password storage. A production system should use bcrypt or Argon2. |
